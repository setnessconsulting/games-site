# Games site architecture

`games-site` is the public arcade shell. Each game keeps its source in a separate repository and
publishes a versioned browser build to the shared private R2 bucket.

## Request flow

1. A visitor opens `https://games.setnessconsulting.com/` and sees the catalog generated by Astro.
2. Each catalog entry gets its own launcher route, for example `/signal-garden/` or
   `/bridge-builder/`.
3. Each playable entry gets a play route, for example `/signal-garden/play/` or
   `/bridge-builder/play/`.
4. Unity and static browser files are requested from `/game-assets/<slug>/<version>/<path>`.
5. The Pages Function validates the approved catalog release and streams the matching object from R2.

Pages hosts the small HTML, CSS, JavaScript, and artwork shell. R2 holds large game artifacts so
the site is not constrained by Pages' per-file asset limit.

## Bridge Builder boundary

`game-bridge-builder` owns Bridge Builder source, tests, build, and release manifest. `games-site`
owns the catalog, launcher, same-origin iframe route, and approved version pointer. The production
Bridge Builder catalog entry stays `coming-soon` during standalone qualification. LevelBest remains
unchanged until the complete evidence and owner-approval gate passes; later LevelBest integration
consumes the exact pinned release artifact and does not copy game source.
